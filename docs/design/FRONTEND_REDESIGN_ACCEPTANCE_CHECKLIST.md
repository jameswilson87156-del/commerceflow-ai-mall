# CommerceFlow 双端前端改造验收清单 V3

## A. 修改前只读基线

- [ ] 记录 `git status --short --branch`、当前分支、HEAD、`git diff --stat`、`git diff --name-status`、未跟踪文件和与本轮目标相关的完整差异。
- [ ] 识别并保留已有业务修改、未跟踪文件、日志、证据和构建产物；绝不 reset、clean、强制 checkout、覆盖或全仓格式化。
- [ ] 对四份现有设计规范记录 Git 状态、SHA-256 与修订前副本。
- [ ] 对两端 package.json、入口、路由、全局 CSS、相关页面和原有 dist 文件清单/大小/SHA-256 记录基线。
- [ ] 实际读取两端路由、页面、公共组件、测试与样式，建立管理端及用户端页面清单。
- [ ] 每页使用 `NOT_STARTED`、`IN_PROGRESS`、`IMPLEMENTED`、`TESTED`、`BROWSER_VERIFIED` 或 `BLOCKED`；代码编辑完成不等于验收完成。

## B. 规范与设计系统自审

- [ ] 只修订 docs/design 中现有四份规范，不另建重复设计文档。
- [ ] 说明两端共用的语义令牌及端侧颜色值/布局变量归属。
- [ ] 说明 CSS 实际导入图、覆盖顺序、重复根变量、硬编码和不 scoped 页面样式的风险。
- [ ] 说明公共组件优先复用、展示中文和技术诊断信息的分界。
- [ ] 说明每批测试、构建、浏览器验收、失败停止/回退与每页状态。
- [ ] 对四份文件做精确差异与修改后哈希检查，确认文档和真实源码一致后再继续。

## C. 基线测试与构建产物保护

管理端目录 `apps/admin-web`：

- [ ] 先读取 package.json，执行真实 `npm test` 脚本，记录目录、命令、退出码、通过/失败/跳过数量和原始失败项。

用户端目录 `apps/mobile-app`：

- [ ] 先读取 package.json，执行真实 `npm test` 脚本，记录同上信息。

构建前：

- [ ] 读取 package.json/Vite 配置确认真实构建脚本和输出目录。
- [ ] 检查输出目录已有内容；优先用独立临时输出，若不能隔离则先做完整、可验证备份。
- [ ] 基线失败不得删测试、放宽断言或记为通过；保存失败原文并判断基线/本轮来源。
- [ ] 不安装新组件库、动画引擎、平台依赖或未知软件。

## D. 页面与样式逐批改造

- [ ] 先复核运营总览作为管理端样板，保留数据、刷新、加载、空数据、错误、重试、鉴权和边界说明。
- [ ] 按真实路由逐页完成管理端所有内部视图（当前 App.vue 中 4 个视图键）和用户端 pages.json 注册的全部 H5 页面（当前 8 条）。
- [ ] 改造每页前阅读页面和依赖组件，确认现有请求、交互、状态、权限和局部样式。
- [ ] 每页完成标题/文案、筛选/表格或购物流程、加载/空/失败/重试、焦点/禁用/选中、窄屏溢出与文字裁切检查。
- [ ] 优先复用管理端 AdminSectionHeader、AdminStatusPill、AdminBoundaryStrip、AdminAuthControl 和用户端 MobileHeader、MobileBottomNav、MobileStatusPill、MobileNotice、MobileMoney、ProductImage。
- [ ] CSS 每批只处理一个明确令牌组、一个共享组件或一个页面；修改前记录哈希与级联来源，不用全局通配或 `!important` 覆盖问题。
- [ ] 只修改前端展示、样式、现有 UI 组件与直接相关的展示交互；不修改 API 路径/参数、字段/枚举、鉴权、后端、数据库、订单/库存/支付/退款逻辑或生产数据。
- [ ] 展示数字、运行模式、状态、AI 结果、订单和商品信息必须来自真实配置/接口；不以虚构内容填满页面。

## E. 每页测试、构建与浏览器验收

每页按以下循环记录证据：

- [ ] 阅读页面与依赖组件 → 记录基线问题 → 最小修改 → 相关现有测试 → 修复本轮失败 → 重跑失败测试和回归 → 检查共享组件影响 → 所属应用全量测试/类型检查/构建 → 浏览器验收。
- [ ] 每个独立故障最多进行三轮有明确根因的修复；仍失败时标 `BLOCKED`，保存日志并继续处理不依赖该故障的页面。
- [ ] 运行真实浏览器页面，并覆盖 1440px、1280px、768px、390px、360px；若已有更严格断点则追加。
- [ ] 实际检查页面加载、滚动/溢出/遮挡/裁切、控制台新增错误、网络失败、按钮/链接/筛选/表单、状态反馈、键盘焦点与禁用态。
- [ ] 记录路由、视口、截图、控制台、网络和交互证据；不能运行的状态标 `BLOCKED`，不得标 `BROWSER_VERIFIED`。
- [ ] 仅在隔离测试环境检查网络契约；不触发真实支付、退款、生产数据写入或未经授权的外部模型请求。
- [ ] 浏览器不可用时记录所有尝试与确切退出码/错误，继续独立可测页面；整体结论只能是 `PARTIAL` 或 `BLOCKED`。

- [ ] 对每个本轮修改文件记录修改前后 SHA-256；将最终状态与启动基线逐项比较。
